# STUNKS web redesign around live Pons flows

The redesign adds a global client-side header and a market-focused landing page around the existing server-read and client-signing architecture. Launch submission still re-reads mutable terms, and trading still re-quotes before approval and signing. The new home surface promotes indexer-backed activity and rankings but drops the freshness result returned with those rankings; it also keeps chain failure behind closed telemetry. **Watch for:** **confirmed** stale or chain-unverifiable market figures can be presented as “real events” on the home page; **confirmed** the compact global wallet control suppresses connection and wrong-network context.

**Verdict**: NEEDS_CHANGES

## High-level view

The home page pairs a live chain snapshot with indexer aggregates, but only Explore renders the indexer’s freshness status. **Confirmed:** the new home figures can be stale or chain-unverifiable while still appearing as current activity.

The compact header shares wallet state globally but hides its normal failure and wrong-network messages. **Confirmed:** signing remains blocked, but recovery instructions and the connected control’s action are not communicated clearly.

## High — Homepage market figures outlive their freshness contract

**Confirmed:** `apps/web/src/app/page.tsx:63-80` passes the live head to `exploreTokens`, whose result includes `staleness`, but the hero and trending table at `:181-205` and `:249-304` read only `stats` and `trending.tokens`. Explore is the only changed route that renders indexed block, chain head, and lag (`apps/web/src/app/explore/page.tsx:106-121`). The landing copy calls the counts “Indexed trade activity” and “real events,” yet nothing distinguishes a current index from one that is minutes behind.

**Confirmed:** when `readChainSnapshot()` fails, the page passes `null` as its chain head. `readStaleness()` marks that state stale, but successful database statistics still render and the chain failure lives inside a closed telemetry disclosure. The prior landing page returned the chain-unreachable state. This is a fail-open presentation change at a financial-data trust boundary. Render the returned staleness prominently for hero metrics and rankings, and retain a visible degraded state when no chain head is available.

## Low — Compact header hides the reason wallet actions cannot proceed

**Confirmed:** the new site header always passes `compact` to `ConnectWallet` (`apps/web/src/components/site-header.tsx:64-69`). Compact mode suppresses no-wallet and connection-error feedback (`apps/web/src/components/wallet.tsx:54-63`) and the wrong-network status and target-chain explanation (`:71-78`). A failed connection or absent injected connector leaves only a disabled “Connect wallet” button; a wrong-chain wallet shows a generic “Switch network” beside a static green “Robinhood Chain” chip. `useCanTransact` still gates both changed signing surfaces, so no unsafe signature is enabled, but recovery is opaque.

**Confirmed:** the connected compact control exposes the shortened address as its visible accessible name, with “Disconnect wallet” only in a tooltip (`apps/web/src/components/wallet.tsx:91-101`). Give it an explicit accessible name such as `Disconnect wallet 0x1234…abcd`, expose status/error text through an accessible status region, and keep “Wrong network — switch to Robinhood Chain” visible rather than relying on color and a generic verb.

</details>
